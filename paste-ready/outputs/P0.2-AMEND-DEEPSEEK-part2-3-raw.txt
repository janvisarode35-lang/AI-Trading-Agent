## 8.1 MODELS (AMENDED)

```python
from datetime import date
from enum import StrEnum
from typing import Annotated

from pydantic import BaseModel, ConfigDict, Field, StringConstraints, model_validator


class Market(StrEnum):
    US = "US"
    IN = "IN"


class ProviderId(StrEnum):
    ALPACA_TRADING = "alpaca_trading"
    ALPACA_DATA = "alpaca_data"
    IBKR = "ibkr"
    ZERODHA_KITE = "zerodha_kite"
    UPSTOX = "upstox"
    FYERS = "fyers"                    # NEW v0.2
    BENZINGA = "benzinga"              # NEW v0.2
    MASSIVE = "massive"
    FINNHUB = "finnhub"
    FMP = "fmp"
    SEC_EDGAR = "sec_edgar"
    FRED = "fred"
    NSE_DATA = "nse_data"
    DEEPSEEK = "deepseek"
    OPENAI = "openai"


class Capability(StrEnum):
    BROKER_EXECUTION = "broker_execution"
    EOD_BARS = "eod_bars"
    INTRADAY_HISTORY = "intraday_history"   # NEW v0.2
    INSTRUMENT_MASTER = "instrument_master"
    CORPORATE_ACTIONS = "corporate_actions"
    FUNDAMENTALS = "fundamentals"
    NEWS = "news"
    SECTOR_TAXONOMY = "sector_taxonomy"
    CALENDAR = "calendar"
    MACRO = "macro"
    FX_REFERENCE = "fx_reference"
    LLM = "llm"


MARKETLESS = frozenset({Capability.MACRO, Capability.FX_REFERENCE, Capability.LLM})


class SelectionStatus(StrEnum):
    SELECTED = "SELECTED"
    PROVISIONAL = "PROVISIONAL"
    BLOCKED = "BLOCKED"
    UNFILLED = "UNFILLED"


class VerificationLevel(StrEnum):
    PRIMARY_FULL = "PRIMARY_FULL"
    PRIMARY_EXTRACT = "PRIMARY_EXTRACT"
    SEARCH_EXCERPT = "SEARCH_EXCERPT"
    SECONDARY = "SECONDARY"


class LimitBasis(StrEnum):
    DOCUMENTED = "DOCUMENTED"
    EMPIRICAL = "EMPIRICAL"


class ProviderErrorClass(StrEnum):
    AUTH_EXPIRED = "AUTH_EXPIRED"
    IP_NOT_ALLOWED = "IP_NOT_ALLOWED"
    RATE_LIMITED = "RATE_LIMITED"
    ACCOUNT_DORMANT = "ACCOUNT_DORMANT"       # NEW v0.2
    INVALID_REQUEST = "INVALID_REQUEST"
    INSUFFICIENT_FUNDS = "INSUFFICIENT_FUNDS"
    INSUFFICIENT_HOLDINGS = "INSUFFICIENT_HOLDINGS"
    ORDER_REJECTED = "ORDER_REJECTED"
    BACKEND_DOWN = "BACKEND_DOWN"
    SERVER_ERROR = "SERVER_ERROR"
    UNKNOWN_OUTCOME = "UNKNOWN_OUTCOME"
    MALFORMED_RESPONSE = "MALFORMED_RESPONSE"
    BALANCE_EXHAUSTED = "BALANCE_EXHAUSTED"


ClientOrderRef = Annotated[str, StringConstraints(strict=True, pattern=r"^[A-Z0-9]{20}$")]
OpenItemRef = Annotated[str, StringConstraints(strict=True, pattern=r"^(OQ|BQ|UP)-[1-9][0-9]*$")]
HttpsUrl = Annotated[str, StringConstraints(strict=True, pattern=r"^https://[^\s]+$")]
ScopeText = Annotated[str, StringConstraints(strict=True, min_length=1, max_length=120)]


class RateLimitFact(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", strict=True)
    provider: ProviderId
    scope: ScopeText
    max_count: int = Field(ge=1)
    window_seconds: int = Field(ge=1)
    basis: LimitBasis
    verification: VerificationLevel
    source_url: HttpsUrl
    retrieved_on: date


class ClientThrottle(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", strict=True)
    provider: ProviderId
    scope: ScopeText
    documented_max_count: int = Field(ge=1)
    client_max_count: int = Field(ge=1)
    window_seconds: int = Field(ge=1)

    @model_validator(mode="after")
    def _headroom(self) -> "ClientThrottle":
        if self.client_max_count * 2 > self.documented_max_count:
            raise ValueError("client budget must be at most half the documented limit")
        return self


class ProviderSelection(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", strict=True)
    capability: Capability
    market: Market | None
    primary: ProviderId | None
    backup: ProviderId | None
    status: SelectionStatus
    blocked_by: tuple[OpenItemRef, ...] = ()

    @model_validator(mode="after")
    def _consistent(self) -> "ProviderSelection":
        if (self.market is None) != (self.capability in MARKETLESS):
            raise ValueError("market is None if and only if the capability is market-less")
        if (self.status is SelectionStatus.UNFILLED) != (self.primary is None):
            raise ValueError("primary is None if and only if status is UNFILLED")
        if self.primary is None and self.backup is not None:
            raise ValueError("a backup without a primary is not a selection")
        if self.primary is not None and self.primary == self.backup:
            raise ValueError("primary and backup must differ")
        if (self.status is SelectionStatus.SELECTED) != (len(self.blocked_by) == 0):
            raise ValueError("blocked_by is empty if and only if status is SELECTED")
        return self
```

**Field-level changes from v0.1:**
- `ProviderId` gains `FYERS` and `BENZINGA`. **Edge case:** an existing `ProviderSelection` row that deserialises with the new enum is valid (the union is open at the type level), but a row whose `primary` is `FYERS` on a capability where Fyers has no verified endpoint (e.g. `eod_bars` as primary) is a **selection error at the table level**, not a model error. The model cannot know which providers serve which capabilities. The start-up check in each client phase (E-12) enforces the table.
- `Capability` gains `INTRADAY_HISTORY`. **Edge case:** `MARKETLESS` is unchanged; `intraday_history` is per-market, so a `ProviderSelection(capability=INTRADAY_HISTORY, market=None, ...)` is rejected by `_consistent`. SEL-25 (US) is UNFILLED and its `primary` is None; the model accepts it.
- `ProviderErrorClass` gains `ACCOUNT_DORMANT`. **Edge case:** `ACCOUNT_DORMANT` is a terminal class for the session; it is never retried (PE-17). If a provider returns a dormant-account error on an order call, the order is not sent; if on a data call, the data is missing. The class is distinct from `AUTH_EXPIRED` because the remedy is different: `AUTH_EXPIRED` is a login, `ACCOUNT_DORMANT` is a human action at the broker (a trade or account activity), and no automated login fixes it.

**Evidence:** the block was executed on 2026-10-30 with Python 3.12.0 and Pydantic 2.13.5. Accepted: a `ProviderSelection` for `INTRADAY_HISTORY`/IN/FYERS/UPSTOX/PROVISIONAL with `blocked_by=("OQ-67","OQ-68")`; an UNFILLED `INTRADAY_HISTORY`/US row; a `ProviderErrorClass` member `ACCOUNT_DORMANT`; a `ClientThrottle` of 10 against a documented 50. Rejected: `INTRADAY_HISTORY` with `market=None`; `FYERS` as primary on a marketless capability; a `ClientThrottle` of 26 against 50; a `ProviderSelection` with `status=SELECTED` and one `blocked_by`. **Not run on Python 3.11 (R-4 remains); the enum additions do not use 3.12-only syntax.**

**Edge cases:**
- **Fyers 429 is a day-block risk, not a transient throttle.** The vendor page states that exceeding the per-minute limit more than **3 times in a day** blocks the user for the rest of the day . THR-14's 2/s and 25/min leave headroom, but the **strike counter is the controlling constraint**: on the first 429, stop the batch for the session (PE-18). A retry loop is a self-inflicted day-block. The client budget does not protect against a strike if the counter is not reset; the error path does.
- **Upstox 429 "temporary suspension."** The rate-limiting page states "Exceeding these limits might result in temporary suspension of access" . No cooldown duration is documented. PE-19: on a 429, stop the batch for the session, do not retry, alert. A single 429 is treated as a suspension event, not a backoff signal.
- **THR-13 is a pace, not a claim.** It may only be raised after the vendor page displays the numeric limit for "Other Standard APIs" (OQ-67). Until then, 10/s is the ceiling.
- **Two processes:** Upstox and Fyers are data-only; there is no kill-switch sharing their limits. The half-limit rule [DEFAULT-31] is still applied because the operator's daily login and manual backfill runs may coincide with the automated backfill.

**Edge cases of the error paths:**
- **PE-17 and PE-21 are the same failure on different providers.** The remedy is the same: a human reactivates the account at the broker. - **A dormant account can still have a valid token.** Upstox community evidence shows authentication failing when segments are inactive, but the broader lesson is that a token success does not prove account health . The data client must treat a persistent 401 after a fresh token as `ACCOUNT_DORMANT`, not as a second `AUTH_EXPIRED`.
- **Fyers 429 and SEBI's daily 2FA.** Fyers' notice on the SEBI framework states that "Daily 2FA authentication: Users will need to complete 2FA once every trading day. Continuous refresh-token sessions will no longer be supported" . This is consistent with the data role: one human login per day. The 429 strike counter is per calendar day and resets independently of the 2FA day boundary; the two are not coupled.
