2.2 What counts as a "day trade" — moot for us, recorded for the register

Under the old rule, a day trade was the purchase and sale of the same security on the same day in a margin account. Partial fills: an order that fills in multiple executions on the same day and is closed the same day is one day trade, counted per round trip, not per fill. Multiple entries and exits in one symbol on one day: each opening transaction paired with a closing transaction is a separate day trade; the old rule's counting was per round trip, with Interpretation /02 providing an alternative calculation method for multiple purchases and sales of the same security on the same day .-
4

Under the replacement, day trades are not counted at all. FINRA's own explanation: "We avoid defining a 'day' in the rule because we don't know how things are going to change. We wanted to make the rule as future-proof as possible" . This is the strongest possible statement that no implementable day-trade-counting logic should exist in our codebase.-
14

2.3 The rolling window and timezone — moot

The old five-business-day window used the broker's business day, which for US equities is the exchange trading day in America/New_York, inclusive of the current day, with half-days counting as full business days for the count. None of this is implemented. It is recorded in the register so that a future reader does not reintroduce it.

2.4 Equity check before or after the fourth trade — moot

The old rule checked equity at the end of the session on which the fourth day trade in the window occurred, against the account's equity in the margin account. Not implemented. The replacement checks intraday margin deficits in real time or at end of day, per the member's choice . We have no margin account, so neither check is implemented.-

2.6 Cash-account rules and the good-faith interaction (Q-P1.1-1 condition 3, blocking #16)

This is the only live constraint, and it is not PDT.

Settlement: US equities settle T+1 under current SEC rules. Sale proceeds are not usable to fund a purchase until settled, unless the broker's display of buying power says otherwise .-

-
19

Good-faith violation: buying with unsettled proceeds and then selling the new security before the prior sale settles. Free-riding: paying for a purchase with the proceeds of that same security's sale. Reg T authorises a 90-day freeze requiring full payment on trade date after a free-riding violation .-
19

Three good-faith violations in 12 months commonly triggers a 90-day settled-funds-only restriction, per broker policy . This is a broker-level policy, not a single FINRA number in the text I retrieved.-
6

Fail-closed implementation: the order gate must read settled cash from the broker, not "buying power." If the field is absent or stale, DENY. If a sell would precede settlement of the purchase, DENY. No netting of unsettled proceeds. This is the Q-P1.1-1 condition 3 answer: the condition is not a PDT equity gate; it is a settled-funds gate.

Edge case: a partial fill on a buy, with the filled portion sold the same day while the remainder settles. The sold portion's proceeds are unsettled until T+1. Any use of those proceeds before settlement is a potential good-faith violation. The gate denies the reuse.

Edge case: an overnight gap that pushes a position above 5% NAV. This is an exposure-rule question, not a PDT question. The exposure rule (EXP-001) handles it.

"""SPEC-P2.9-PDT verification. Pins the regulatory regime, not a magic number.

The constitutional numbers are pinned in tests/verify_p13_config.py. This file pins
the REGULATORY regime that replaced the PDT floor, because a frozen spec carried
the number 25,000 without a register entry (STAGE-1-GAP-AUDIT §4 item 4).

A failure here means one of:
  (a) someone reintroduced a $25,000 equity gate into the policy;
  (b) someone changed the replacement effective date without a register update;
  (c) the register entry PDT-1 was deleted.

None of those may happen silently.
"""
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT / "src"))


def require(cond, msg=""):
    if not cond:
        raise AssertionError(msg)


PASS, FAIL = [], []


def check(name, fn):
    try:
        fn()
        PASS.append(name)
    except Exception as e:  # noqa: BLE001
        FAIL.append(f"{name}: {type(e).__name__}: {e}")


# ---- the regime constants ---------------------------------------------------
# These are the pinned facts. A change here requires a new register entry and an
# Owner-signed amendment, because it changes which regulatory control is live.
PDT_REPLACEMENT_EFFECTIVE_DATE = "2026-06-04"   # FINRA Notice 26-10
PDT_REPLACEMENT_PHASE_IN_END  = "2027-10-20"    # end of 18-month phase-in
PDT_LEGACY_THRESHOLD_USD      = 25000           # HISTORICAL ONLY. Never a gate.
PDT_STATUS                    = "REPLACED"      # not "ACTIVE", not "UNVERIFIED"


def t_pdt_is_not_an_active_control():
    """The single load-bearing assertion: 25,000 must not appear as an active
    threshold anywhere in the policy document."""
    from config import loader as L
    cfg = L.PolicyLoader(ROOT / "config").load(require_signature=False)
    for r in cfg.document.rules:
        # A rule with threshold 25000 and a pdt-ish id would be a regression.
        tid = (r.id or "").lower()
        desc = (r.description or "").lower()
        if "pdt" in tid or "pattern day" in desc or "day trade" in desc:
            require(
                r.threshold != PDT_LEGACY_THRESHOLD_USD,
                f"rule {r.id} reintroduces the obsolete PDT threshold",
            )
            # Stronger: no rule may gate on day-trade count at all.
            require(
                "day_trade_count" not in (r.inputs or []),
                f"rule {r.id} gates on day-trade count, which no longer exists",
            )


def t_register_entry_pdt_1_exists_and_is_marked_resolved():
    """The register entry is the audit trail. It must not be deleted or reopened."""
    freeze = (ROOT / "docs" / "specs" / "STAGE-0-FREEZE.md").read_text(encoding="utf-8")
    require("PDT-1" in freeze, "register entry PDT-1 is missing from STAGE-0-FREEZE §6")
    require(
        "OBSOLETE" in freeze or "obsolete" in freeze,
        "PDT-1 must state the figure is obsolete, not merely unverified",
    )
    require(
        PDT_REPLACEMENT_EFFECTIVE_DATE in freeze,
        "the replacement effective date must appear in the register entry",
    )
    # And the legacy number must be labelled historical, not live.
    require(
        "never a live control" in freeze.lower() or "historical only" in freeze.lower(),
        "the 25,000 figure must be labelled historical, not live",
    )


def t_phase_in_date_is_pinned():
    """The phase-in end date is the last date a broker may still apply the old rule.
    After this date, any PDT gate in any adapter is a defect."""
    require(PDT_REPLACEMENT_PHASE_IN_END == "2027-10-20", PDT_REPLACEMENT_PHASE_IN_END)
    # An adapter that reads a per-broker migration flag must default to NEW.
    from provider.enums import ProviderId  # noqa: F401
    # If a migration flag exists, its default must be the new regime.
    # (If no flag exists, the replacement is assumed adopted; this assertion is
    #  a tripwire for the day someone adds one with the wrong default.)
    try:
        from provider.spec import ProviderSpec
        import inspect
        src = inspect.getsource(ProviderSpec)
        if "pdt_migrated" in src:
            require(
                "pdt_migrated: bool = True" in src,
                "a per-broker PDT migration flag exists and does not default to the new regime",
            )
    except ImportError:
        pass  # no provider spec yet in this phase


def t_alpaca_docs_claim_is_recorded():
    """Alpaca's own docs say PDT protection no longer rejects orders. If that
    changes, the adapter must not assume it."""
    # This is a documentary assertion, not a runtime one: the fact is recorded
    # in the spec's §10.4 limits table as a verified statement. If the spec is
    # edited to remove it, this fails.
    spec = (ROOT / "docs" / "specs" / "SPEC-P0.2-PROVIDERS.md").read_text(encoding="utf-8")
    require(
        "PDT" in spec or "pattern day" in spec.lower(),
        "SPEC-P0.2 must record Alpaca's PDT abolition; it is the primary US broker",
    )


def t_cash_account_constraint_is_not_pdt():
    """The live control is settled funds, not PDT. This asserts the correct control
    is present in the policy, so that deleting PDT did not delete the real gate."""
    from config import loader as L
    cfg = L.PolicyLoader(ROOT / "config").load(require_signature=False)
    ids = {r.id for r in cfg.document.rules}
    # CASH-001 is the settlement/good-faith rule used by verify_p13_config.py
    require(
        "CASH-001" in ids,
        "CASH-001 (settled funds) is missing; removing PDT must not remove the live control",
    )


for _n, _f in sorted((n, f) for n, f in list(globals().items()) if n.startswith("t_")):
    check(_n, _f)

print(f"PASSED {len(PASS)}")
for f in FAIL:
    print("FAILED", f)
sys.exit(1 if FAIL else 0)
