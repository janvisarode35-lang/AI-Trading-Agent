The new field proves that a licence record exists, not whose licence it is.

**Defect: MEDIUM, §8.1 validator and the §6.3 P1.3 resolution of `backup_licence_audit_id`**

[Certain] The diff never binds a licence record to the provider it is meant to license. Nothing stops both ids from naming the same record, and "resolves it the same way" only requires that the record exists.

Input that goes wrong:
- SEL-4 is marked `SELECTED`, `PUBLICATION`, with `licence_audit_id = U` (the record of Upstox's licence).
- The backup stays `FYERS`, with `backup_licence_audit_id = U`.

What happens:
1. The validator accepts the row.
2. P1.3 finds that `U` exists.
3. `row_cleared(FYERS, EOD_BARS, IN, …)` returns true.
4. Fyers bars enter a published signal under Upstox's licence, which is exactly what F-82 and OQ-68 forbid.

[Likely] The primary id has the same gap, but the backup field makes it easy to trigger.

**Fix:**
- In the validator, require `backup_licence_audit_id != licence_audit_id`.
- Require P1.3 to check that each record names its own provider, capability and market, as MB-E4 checks a switch's market and `legal_review_ref`.
- Add a test with the shared id.
