**A — MEDIUM — §8.1 `ProviderSelection` validator; SEL-19; STACK-1; PE-14**

[Certain] A row cleared for publication must have `backup is None`, but STACK-1 fixes "DeepSeek (primary) + GPT-4o-mini (fallback)" as not open to redesign.

Input: `{capability: llm, market: null, primary: deepseek, backup: openai, status: SELECTED, licensed_use: PUBLICATION, licence_audit_id: <uuid>}` → `ValueError`, so E-11 rejects the whole set.

So the LLM row can clear only by deleting a fixed-stack fallback. If it is deleted anyway, a contradiction follows:
1. PE-14 still makes "one call to the fallback".
2. `row_cleared(OPENAI, LLM, …)` is then false.
3. E-36 discards that output.

OQ-79 does not cover this. It asks which capabilities count, not whether a fixed fallback can live on a cleared row.

**Fix:**
- Give the LLM path its own rule, either a per-provider licence field for market-less rows or an LLM exemption.
- Or record this as a STACK-1 conflict in §2.

**B — MEDIUM — §8.3 Redis edge case: "one full window has passed"**

[Certain] The text does not say which window.

[Likely] Read as the shortest window (1 s), the input goes wrong like this:
1. 1,000 Upstox calls run between 18:00 and 18:20.
2. Redis blips for 2 s at 18:20, and the client waits 1 s.
3. The counter is back at 0, and 1,000 more calls run by 18:30.
4. That is 2,000 calls in 30 minutes, the documented limit itself, so PE-23 fires.

For Fyers, the same blip resets the 2,500-a-day count mid-day.

**Fix:** "the longest window of every scope of that account". For Fyers, that means the rest of the `Asia/Kolkata` day.
